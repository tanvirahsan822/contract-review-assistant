# Docket — Contract Review Assistant

A small, safe AI-assisted contract review prototype built for the Intra IUB Hackathon (Final Round).

**Live demo:** _add your deployed link here after publishing (see Deployment below)_

## What it does

Docket walks through the required workflow for every clause it checks:

1. Select a contract
2. Find the clause text for a given category (keyword-triggered sentence match — never generated)
3. Retrieve the matching company standard (fixed, approved reference data)
4. Compare the two and compute a **Low / Medium / High / Not Enough Information** risk level
5. Explain the reason in one plain sentence
6. Show the evidence: the exact contract sentence, the exact standard text, and both sources
7. Require human review before any result is treated as final (Approve / Reject / Mark for Review / add feedback)

Supported clause types: **Payment, Termination, Automatic Renewal**.

## Why it doesn't hallucinate

- The clause "finder" never generates text. It splits the contract into sentences and returns the **exact sentence** that matches a keyword trigger for the selected clause type (e.g. "renew" → Automatic Renewal). If no sentence matches, nothing is returned for that clause.
- The company standards are fixed, hardcoded reference data — not retrieved from the open web or generated by a model.
- Risk levels come from a small rule table (e.g. compare the number of days found in the contract sentence against the standard's threshold) — not from open-ended reasoning.
- If a clause isn't found, or a number can't be reliably extracted from it, the system returns exactly:
  _"Not enough information to make a reliable assessment."_
  It never invents a clause, a number, or a legal conclusion.
- Every risk result is shown with its evidence (clause + standard + sources) side by side — there is no risk label without the text that produced it.
- The interface states throughout that this is an assistive tool, not legal advice, and every result carries a required human-review step.

## Tech choice

Plain HTML/CSS/JS, rule-based keyword matching + a small comparison rule table. No external API calls, no backend, no API key. This keeps the whole system auditable end-to-end in the browser — a deliberate choice for the "simplest reliable solution" principle — and it means private contract text never leaves the user's machine.

(A production version would likely add an LLM step to *locate* clauses in messier, unstructured contracts, but would still constrain the model to only extract/quote existing text — never generate clause language — and would keep the same evidence-first, human-in-the-loop structure.)

## Presentation notes (for judges' Q&A)

- **How the system finds the correct clause:** sentence-level keyword triggers per clause type (e.g. "invoice"/"paid" for Payment, "terminat" for Termination, "renew" for Automatic Renewal). The matched sentence is quoted verbatim as evidence.
- **How it compares clause vs. standard:** extracts the numeric term (days) from the matched sentence via regex and checks it against a fixed threshold from the company standard for that clause type.
- **How it prevents made-up answers:** the system only ever echoes real contract text and fixed standard text; risk labels come from explicit rules, not free-form generation; missing information produces the fixed safe-fallback string instead of a guess.
- **Scaling to more contracts/clause types:** swap the keyword-trigger step for an LLM-based extractor that is prompted to quote-only (never paraphrase or invent) from the source contract, and expand the standards table; keep the same evidence + human-review structure.
- **Protecting private contracts:** current version processes everything client-side (no network calls at all). A hosted version would add encryption in transit/at rest, no long-term retention of contract text, and role-based access to review actions.
- **What we'd improve with more time:** OCR/PDF ingestion, more clause types, an LLM-assisted extractor for non-templated contracts, an audit log of review decisions, and multi-clause "not enough information" nuance (e.g. partial matches).

## Important

This tool is an assistant only. It does not provide legal advice, and every result requires human review before any decision is made.
